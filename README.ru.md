Визуальный редактор интерфейсов LVGL с общей моделью проекта и тремя целями: **C/LVGL**, **LispBM/VESC** и **BASIC/IoTEmbedded**. Редактор отвечает за проектирование, генерацию, преобразование ресурсов, проверку цели и упаковку результата. Хосты, например HmiCraft, выбирают цель и профиль устройства/API и используют результат.

PR [#3](https://github.com/IoTSharp/lvgl-editor/pull/3) предоставляет направление LispBM/VESC. Интеграция сохраняет процесс и тесты C и добавляет BASIC. Работа продолжается; интеграция исходников, генерация, компиляция, выполнение скриптов и реальные устройства проверяются отдельно. См. [английскую дорожную карту](ROADMAP.md), [китайскую дорожную карту](ROADMAP.zh-CN.md) и [правила проекта](AGENTS.md).

## Цели генерации

| Идентификатор | Результат | Границы проверки |
|---|---|---|
| `c-lvgl` | Заголовки/исходники C, события/логика и ресурсы цели | Генератор сохранен, общий контракт исходников проверен локально; целевая компиляция еще не проверена |
| `lispbm-vesc` | Компоновка/события Lisp и ресурсы для версионируемого моста VESC/LVGL | Интеграция PR #3; нужные API есть не в каждой прошивке VESC |
| `basic-iotembedded` | Компоновка BASIC, отдельные пользовательские модули событий, ресурсы и манифест | Первый этап: базовая генерация компоновки/событий и контракт пакета; HmiCraft runtime и плата проверяются отдельно |

Выберите цель в **New Project** или измените ее в **Project Settings**, если хост разрешает. Самостоятельный редактор по умолчанию использует C, вход HmiCraft для собственных устройств — BASIC. Проект должен сохранять цель/профиль и пользовательские модули каждого языка. Рукописный C/Lisp/BASIC не переводится автоматически. Смена цели, повторная генерация, переименование, сохранение/открытие и восстановление не должны перезаписывать логику пользователя. Неподдерживаемые функции и несовместимые профили требуют диагностики с указанием места и блокируют экспорт; пустая реализация не считается успехом. Состояния отслеживаются в GEN-01/02/07/09/10.

Среда React/TypeScript включает палитру, холст, иерархию/свойства, страницы, события, графы React Flow, Monaco, ресурсы и сохранение проекта. Canvas показывает внешний вид; C/WASM и скрипты требуют соответствующих адаптеров. HmiCraft отвечает за профили, HMI runtime, загрузку/развертывание и устройства, IoTEmbedded — за общие MCU/RTOS/BSP, драйверы и BASIC. Генераторы независимы от исходников/сервисов HmiCraft, не подключаются к устройствам, не прошивают их и не записывают значения PLC.

## Разработка и проверки

Используйте lockfile и совместимые Node.js/npm: `npm ci`, затем `npm run dev`; Vite выводит локальный адрес. Проверки: `npm run build`, `npm test`, `node scripts/check-docs-sync.mjs`. `build` проверяет TypeScript перед Vite; `build:web` только собирает файлы и не заменяет проверку. Для статического размещения настройте `VITE_ENABLE_COMPILE_PREVIEW=false` и соответствующий `VITE_BASE_PATH`; не публикуйте сервис компиляции для разработки. Тесты C требуют настроенных путей LVGL/компилятора; пропуски записываются явно.

Историческая проверка **2026-10-10** зафиксировала успешную сборку, ошибки TypeScript и **386 успешных / 4 неуспешных** теста Vitest; тесты компиляции C для специальной среды не запускались. Сохраняйте ошибки и последующие исправления в [CHANGELOG](CHANGELOG.md) и дорожной карте. Значок сборки не доказывает готовность к эксплуатации или работу оборудования.

Версии LVGL, runtime API, формата ресурсов, платы/профиля, схемы редактора и пакета управляются отдельно. Шрифты и упаковка должны соответствовать цели; веб-сборка не доказывает совместимость ABI. Интерфейс должен по умолчанию использовать английский и поддерживать переключение на китайский/русский; GEN-12 отдельно отслеживает реализацию и полную проверку UI, независимо от перевода документации.

## Документация и распространение

Английский — основная версия. Три README имеют общие revision/состояния, две дорожные карты — одинаковые идентификаторы/состояния всех задач. Обновляйте все языки в одном изменении и запускайте проверку. Публичные исходники, лицензия, выпуск и проверка устройства — отдельные состояния.

Исходный README заявлял MIT, но в зафиксированной базе нет общего LICENSE. Права на исходники/ресурсы/WASM и сторонние уведомления еще требуют проверки; это изменение не предоставляет новую лицензию. Сохраняйте сведения об авторах; учетные данные клиентов, частная промышленная логика и неразрешенные ресурсы не должны попасть в публичный репозиторий.

## Первый этап BASIC и API

[src/output/index.ts](src/output/index.ts) предоставляет `generateTargetSource(input)` для синхронного просмотра исходников и `generateTargetProject(input)` для асинхронной обработки ресурсов, хешей и манифеста. `OutputBundle` в [types.ts](src/output/types.ts) содержит target/files/issues/manifest/sourceMap и `deployable=false`: это артефакт контракта исходного кода.

BASIC сейчас поддерживает `obj`, `btn`, `label`, `slider`, `bar`, `switch`, `checkbox`, абсолютную компоновку в пикселях, базовые стили default, `navigate/show/hide/enable/disable/setText/setValue` и пользовательские модули событий. Графы, привязки, анимация, изображения/шрифты и неподдерживаемые расширенные стили блокируют экспорт. Файлы: `main.bas`, `generated/layout.bas`, `generated/events.bas`, `user/events.bas`, `api-contract.json`, `source-map.json`, `manifest.json`. `hmicraft-hmi-basic/1-draft` не зарегистрирован в IoTEmbedded; вложенные импорты требуют будущего загрузчика HmiCraft. Генерация не завершает проверку runtime или устройства.

GEN-13 закрепляет профили C/LVGL: `cIntegrationProfile` по умолчанию равен `generic` для совместимости старых проектов; доступны `stm32cube-hal` (STM32CubeMX/CubeIDE HAL) и `rt-thread-scons` (стандартный BSP RT-Thread/SCons). Выбор сохраняется при записи/открытии/экспорте. Начальный контракт размещает файлы STM32 в `Core/Src/hmi` / `Core/Inc/hmi`, RT-Thread — в `applications/hmi` с `SConscript`, и включает `integration-contract.json`. Конкретные .ioc/BSP, целевая сборка и проверка платы не входят в этот этап. Профили — настройки внутри `c-lvgl`, а не дополнительные языки. BASIC имеет начальные карты исходников; карты C/Lisp пока пустые и требуют дальнейшей проверки.

### Локальная проверка — 2026-10-11

Vitest: **509 успешных / 48 пропущенных тестов компиляции C**. Фактическая команда `npm run build` (TypeScript `tsc -b` и Vite) завершилась с кодом **0**. В браузере прошли экспорт ZIP и JSON проекта для C, LispBM и BASIC на примере из двух компонентов со встроенным событием и отдельными модулями каждого языка. Проверены переключение английского/китайского/русского без перезагрузки и сохранение/восстановление цели BASIC после перезагрузки. Все шесть ZIP прошли независимую проверку путей, длины файлов и SHA256. Удаленное слияние PR еще ожидает подтверждения; GEN-09 остается partial: это доказательство для небольшого примера пакета исходников, а не для широкого набора ресурсов, целевого runtime или оборудования.

См. [отчет о проверке](docs/verification-pr3-2026-10-11.md) и [общий пример](samples/three-targets.lvgl.json). Сборки с фиксированными LVGL/.ioc/BSP, выполнение моста/скриптов LispBM, загрузка BASIC в IoTEmbedded, передача на устройство и промышленная приемка не проверены. Исторические ошибки сохранены.
